## 1. 문장은 순서대로 실행되지만 함수 정의는 호출이 아니다
```c
int add_one(int number)
{
    return number + 1;
}

int main(void)
{
    int count = 10;
    int saved = count;
    count = add_one(count);
    return 0;
}
```
count에 10을 넣고 그 값을 saved에 복사한다. add_one()에는 10의 복사본이 전달되고, 반환된 11을 count에 저장한다. 마지막 값은 count=11, saved=10이다. return 0은 main의 반환값이며 count를 0으로 바꾸지 않는다.
함수 정의는 실행할 내용을 적어 둔 것이다. 일반적인 함수 호출은 함수 안에서 수행하며, 표준 C에서는 함수 정의를 다른 함수의 중괄호 안에 넣지 않는다. 아래 수업 과제의 main 내부 함수 정의는 GNU 확장에 의존하는 형태이므로 재작성할 때 함수들을 main 밖으로 옮긴다.
## 2. 반복문에서 초기화 위치가 중요한 이유
```c
int count = 0;
while (count < 3)
{
    count = count + 1;
}
```
조건은 본문에 들어가기 전에 검사한다. count는 0, 1, 2일 때 본문을 실행하고, 3이 되면 종료한다. 반대로 본문 안에서 매번 int count = 0으로 선언하면 그 변수는 매 반복마다 다시 0으로 초기화된다.
if/else는 둘 중 한 블록을 선택한다. 독립된 if 두 개는 앞에서 값이 바뀐 뒤 두 번째 조건을 다시 검사하므로 같은 동작이 아니다.
## 3. 문자, 문자열, 크기를 구분하기
C에서 'A'는 int형 문자 상수다. 현재 STM32 GCC 환경에서는 sizeof('A')가 4이고, char ch = 'A'로 만든 ch의 크기는 1이다. "A"는 문자 A와 끝 표시 '\0'을 포함한 char 배열이므로 sizeof("A")는 2다. 문자 값 65와 그 값을 담는 자료형의 크기를 혼동하지 않는다.
int가 항상 모든 환경에서 4바이트인 것은 아니다. 현재 타깃의 크기는 sizeof로 확인한다. STM32F411 환경에서는 1바이트가 8비트이며 uint8_t/uint16_t/uint32_t는 각각 8/16/32비트 정수형이다.
C와 Python의 차이를 “C만 CPU에 명령하고 Python은 불가능”으로 외우지 않는다. 둘 다 결국 CPU에서 실행된다. C는 자료형·주소·메모리 배치를 명시적으로 다루기 쉽고, 일반적인 Python 환경은 런타임이 객체와 메모리 관리를 더 많이 맡는다.
문법 근거: [C11 초안 6.4.4.4·6.4.5](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf).
## 4. FND는 숫자를 이해하지 못한다
FND는 여러 LED 세그먼트를 묶은 표시 장치다. 숫자 2를 표시하려면 해당 모양에 필요한 A·B·G·E·D를 켜야 한다. 코드에서는 숫자를 세그먼트 패턴으로 바꾸고, 어느 자리를 켤지도 정한다.
공통 애노드/캐소드와 자리 선택 회로에 따라 ON/OFF 논리가 달라진다. 수업 코드의 HIGH/LOW를 다른 FND에 그대로 적용하지 않는다.
예를 들어 1234의 각 자릿값은 다음과 같이 구한다.
```c
int ones      = number % 10;
int tens      = (number / 10) % 10;
int hundreds  = (number / 100) % 10;
int thousands = (number / 1000) % 10;
```
정수 나눗셈은 이 양수 예제에서 소수 부분을 버리고, %는 나머지를 구한다. 따라서 1234/10은 123, 123%10은 3이다.
## 5. 표시 스캔과 숫자 증가는 서로 다른 작업

한 번에 한 자리만 켜고 빠르게 다음 자리로 이동하면 네 자리가 함께 켜진 것처럼 보인다. 자리 변경 시에는 모든 자리 OFF, 세그먼트 패턴 변경, 선택한 자리 ON 순서를 사용하면 이전 자리의 잔상이 섞이는 고스팅을 줄일 수 있다.
**자리 스캔**은 화면을 유지하는 작업이고 **카운터 증가**는 표시할 숫자를 바꾸는 작업이다. 숫자를 100 ms마다 증가시켜도 그 사이 자리 스캔은 계속해야 한다. 100 ms 동안 한 자리에 멈추면 깜빡임이나 밝기 차이가 생긴다.

## 6. 함수로 나누는 이유와 점검
숫자→패턴 변환, 자리 선택, 전체 표시, 숫자 증가를 나누면 잘못된 부분만 따로 확인할 수 있다. main은 전체 순서를 표현하고 각 함수는 작은 책임을 맡는다.
printf로 값을 보려면 UART 설정만으로 끝나지 않는다. printf의 출력 경로를 UART 송신에 연결하는 리타기팅과 터미널의 baud rate 등 통신 설정도 맞아야 한다.
**혼자 해볼 것:** 5072의 각 자릿값을 계산하고, 9999 다음을 0000으로 만드는 조건을 적는다. 숫자 7의 일반적인 세그먼트는 A·B·C이며 수업 원본처럼 F를 추가한 모양을 사용할지는 의도적으로 선택한다.
