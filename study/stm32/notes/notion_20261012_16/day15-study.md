# 학습 정리 · C 메모리에서 GPIO 레지스터까지
> 목표: 포인터와 구조체가 하드웨어 제어 코드로 연결되는 과정을 이해한다. 원본 코드의 자료형은 유지하고, 잘못된 설명과 연산만 구분해 바로잡는다.

## 1. 메모리 배치를 한 줄 그림으로 외우면 안 되는 이유
STM32 프로젝트의 Flash와 RAM은 서로 다른 주소 영역이다. 현재 링커 스크립트는 Flash 시작을 0x08000000, RAM 시작을 0x20000000으로 정한다. 모든 영역이 하나의 연속 공간에 text, data, heap, stack 순으로 붙는다는 그림은 이 프로젝트에 그대로 적용되지 않는다.
- .text: 실행할 기계어. 이 프로젝트에서는 Flash에 배치한다.
- .rodata: 읽기 전용 데이터. 이 프로젝트에서는 Flash에 배치한다.
- .data: 초기값이 있는 변경 가능한 전역·정적 변수. 초기값은 Flash에 보관되고 시작 코드가 RAM으로 복사한다.
- .bss: 0으로 초기화되는 전역·정적 변수. 시작 코드가 RAM을 0으로 만든다. “초기화 안 됐으니 쓰레기 값”이라는 뜻이 아니다.
- stack: 함수 호출·자동 변수·예외 진입 문맥 등에 쓰는 영역. 실제 지역 변수는 레지스터로 최적화될 수도 있다.
- heap: malloc 등 동적 할당에서 사용하는 영역. 현재 작은 GPIO 실습에서 반드시 사용할 필요는 없다.
일반 지역 변수의 수명과 파일 내부 static 변수의 수명은 다르다. 파일 내부 static은 프로그램 실행 동안 값을 유지하면서 이름의 사용 범위를 해당 소스 파일로 제한한다.
## 2. 배열, 문자열, const 설명 바로잡기
배열 이름이 언제나 주소 그 자체인 것은 아니다. 대부분의 식에서 첫 원소의 포인터로 변환된다. 배열 전체를 =로 다시 대입할 수 없는 이유는 배열이 수정 가능한 대입 대상이 아니기 때문이며, “주소에 주소 대입이 불가능해서”가 아니다. 포인터 변수에는 호환되는 주소를 대입할 수 있다.
일반 정수 배열은 정수를 담고, 포인터 배열은 주소를 담는다.
```c
int values[3] = {10, 20, 30};
int *links[3] = {&values[0], &values[1], &values[2]};
```
문자 'A'는 문자 코드 값을 표현한다. 문자열 "A"는 끝의 '\0'을 포함하는 배열이며 많은 식에서 첫 문자의 주소로 변환된다. “C의 문자는 주소를 반환한다”는 설명은 문자와 문자열을 혼동한 것이다.
const는 해당 경로로 값을 수정하지 못하게 제한하는 자료형 한정자다. 모든 런타임 오류를 없애거나 자동으로 Flash 배치를 보장하지 않는다. const int *p는 *p 수정 금지, int * const p는 p에 저장한 주소 변경 금지다.
문법 근거: [C11 초안 6.3.2.1·6.7.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf).
## 3. 문자열 함수와 함수 포인터
strcpy(d, s)는 s부터 '\0'까지 문자 데이터를 d의 버퍼에 복사한다. 주소만 복사하는 함수가 아니다. 목적지 공간은 끝 표시를 포함해 충분해야 한다.
strcat은 기존 목적지 문자열 끝에 이어 붙인다. strcmp는 같으면 0, 다르면 음수 또는 양수를 반환하며 정확히 -1/1만 나온다고 가정하지 않는다. strchr는 찾은 문자의 위치를 가리키는 포인터, 없으면 NULL을 반환한다.
함수도 호출할 위치를 포인터로 보관할 수 있다.
```c
int add(int a, int b) { return a + b; }
int (*fp)(int, int) = add;
/* 함수 안에서 사용: int result = fp(2, 3); */
```
fp는 int 두 개를 받아 int를 돌려주는 함수의 포인터다. 함수 포인터 문법에서는 (*fp)의 괄호가 중요하다. free는 동적으로 할당받은 공간을 할당기에 반환하며, 일반 지역 변수의 주소나 이미 반환한 주소를 넘기면 안 된다.
## 4. 구조체가 레지스터 지도가 되는 과정
일반 구조체는 관련 값을 묶는 그릇이다. 장치 헤더의 GPIO_TypeDef는 GPIO 레지스터의 순서와 간격을 자료형으로 표현한다. GPIOA는 그 구조를 GPIOA의 고정 하드웨어 주소에서 바라보게 하는 포인터 매크로다.
```c
GPIOA->ODR
```
이는 “GPIOA가 가리키는 장치 구조에서 ODR 레지스터에 접근한다”는 뜻이다. 일반 RAM 구조체를 새로 만드는 동작이 아니다.
```c
*(volatile uint32_t *)(0x40020000 + 0x14)
```
주소 계산은 GPIOA 기준 주소에 ODR 오프셋을 더하는 것이다. 형 변환은 그 주소를 32비트 대상의 포인터로 해석하게 하고, 바깥 *는 실제 그 위치에 접근한다. volatile은 하드웨어 때문에 값이 바뀔 수 있는 접근을 컴파일러가 임의로 생략·캐시하는 것을 제한한다. 동시성이나 원자성을 보장하는 기능은 아니다.
## 5. GPIO 설정을 읽는 순서
1. RCC에서 해당 포트 클럭을 켠다.
2. 출력 초기값을 정한다.
3. MODER에서 핀의 입력·출력·대체 기능·아날로그 모드를 정한다.
4. OTYPER, OSPEEDR, PUPDR를 회로에 맞게 정한다.
5. IDR로 입력을 읽거나 ODR/BSRR로 출력을 바꾼다.
MODER는 핀마다 2비트다. PA5는 bit 11:10을 사용하고 출력 모드는 01이다. OSPEEDR는 출력 에지의 전기적 속도 설정이지 LED 깜빡임 주기나 CPU 클럭을 설정하는 항목이 아니다.
Push-pull은 HIGH와 LOW를 능동 구동한다. Open-drain은 LOW로 당기거나 출력을 해제하며, HIGH는 풀업 등으로 형성한다. “외부 전압을 쓰면 open-drain”만으로 정의하지 않는다.
## 6. 비트 연산과 원본 코드의 오류
```c
reg |=  (1 << 4);   // bit 4를 1로
reg &= ~(1 << 3);   // bit 3을 0으로
reg ^=  (1 << 5);   // bit 5를 반대로
```
이 예제는 작은 비트 번호로 연산 원리를 설명한다. 실제 레지스터 접근은 해당 폭과 자료형을 따른다.
원본의 1 <<< 5는 C 연산자가 아니므로 1 << 5로 고친다. 특정 비트만 켜려는 위치에 |= ~(1 << 10)을 쓰면 거의 모든 다른 비트가 1이 된다. 2비트 필드는 기존 두 비트를 지운 뒤 원하는 값을 넣어야 한다.
```c
/* GPIOA 클럭이 활성화된 뒤: PA5 출력 모드 */
GPIOA->MODER &= ~(3 << 10);
GPIOA->MODER |=  (1 << 10);
```
BSRR의 하위 16비트는 해당 출력 비트 set, 상위 16비트는 reset에 사용한다. 읽기-수정-쓰기를 피할 수 있지만, ODR을 먼저 읽어 만드는 토글 전체가 다른 실행 흐름과의 경쟁까지 자동 해결하는 것은 아니다.
레지스터 근거: [STM32F411 RM0383 GPIO/RCC](https://www.st.com/resource/en/reference_manual/dm00119316-stm32f411xce-advanced-armbased-32bit-mcus-stmicroelectronics.pdf).
## 7. 오늘의 연결과 복습
HAL_GPIO_Init()은 설정 구조체를 받아 위 레지스터 설정을 대신 수행한다. 직접 제어를 한 번 이해하면 HAL이 숨겨 놓은 작업을 설명할 수 있다. HAL을 쓰더라도 OS 없이 실행하면 bare-metal 시스템일 수 있다. “bare-metal=HAL 미사용”은 같은 뜻이 아니다.
**복습:** GPIO_InitTypeDef의 Pin/Mode/Pull/Speed가 무엇을 설정하는지 주석으로 설명한다. .ioc 설정, 생성된 초기화 코드, SFR 레지스터 값을 서로 대조한다.
