# 학습 정리 · 보드 설정에서 LED 제어까지
> 목표: 핀을 설정한 뒤 코드 한 줄이 실제 LED에 어떻게 연결되는지 설명한다. 기존 수업 캡처와 과제 자료는 아래에 보존했다.
<table_of_contents/>
## 1. 왜 CubeMX부터 사용하는가
STM32F411RE는 CPU, Flash, RAM, GPIO와 타이머 같은 주변장치가 한 칩에 들어 있는 MCU다. CPU가 C 문장을 그대로 읽는 것은 아니다. 개발 도구가 C 소스를 컴파일하고 링크해 실행 파일을 만들고, ST-LINK가 프로그램을 Flash에 기록한다. 리셋 후 시작 코드가 RAM 초기화 등을 수행하고 main()을 호출한다.
CubeMX는 핀·클럭·주변장치 초기화 코드를 생성한다. CubeIDE는 편집·빌드·다운로드·디버깅을 담당한다. VS Code로 같은 파일을 편집해도 되지만, 저장·빌드·보드 다운로드는 각각 별개의 단계다.
## 2. 코드, 변수, 주변장치는 어디에 있는가
- Flash: 프로그램과 상수 등을 보관한다. 전원을 꺼도 유지된다.
- RAM: 실행 중 변경되는 변수와 스택 등의 작업 공간이다. 전원을 끄면 유지되지 않는다.
- 주변장치 레지스터: GPIO 모드나 출력 상태를 제어하는 하드웨어 저장 공간이다. RAM의 일반 변수와 역할이 다르지만 CPU는 정해진 주소로 접근한다.
STM32F411RE의 Flash는 512 KB, SRAM은 128 KB다. 실제 프로그램의 배치는 링커 스크립트가 정한다. 지역 변수는 최적화에 따라 CPU 레지스터에 놓일 수도 있으므로 모든 C 변수가 항상 RAM에 독립된 칸을 차지한다고 단정하지 않는다.
## 3. 핀을 읽는 순서
PB15는 GPIOB 포트의 15번 비트에 해당하는 핀이다. 패키지의 물리적인 15번 다리라는 뜻이 아니다. HAL에서는 포트 GPIOB와 핀 마스크 GPIO_PIN_15를 함께 전달한다.
```c
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_15, GPIO_PIN_SET);
```
이 코드는 초기화된 PB15 출력에 HIGH를 요청한다. HIGH가 실제 LED ON인지 여부는 LED 연결 방향과 구동 회로에 달려 있다. LED_Button_driver 실습은 HIGH=ON을 가정한다.
초기화는 포트 클럭 활성화, 출력 초기값 설정, 핀 모드·출력 형식·풀업/풀다운·속도 설정으로 나누어 읽는다. 설정 구조체를 작성한 뒤 HAL_GPIO_Init()에 주소를 전달하면 HAL이 해당 GPIO 레지스터를 설정한다.
## 4. 버튼은 전류가 아니라 입력 전압 수준을 읽는다
풀업 버튼의 기본 형태는 입력 핀을 저항을 통해 전원에 연결하고, 버튼을 누르면 입력 핀을 GND에 연결하는 것이다. 이 회로에서는 뗐을 때 HIGH, 눌렀을 때 LOW다. 저항이 전원과 GND 사이의 전류를 제한한다.
GPIO 입력은 입력 노드의 전압을 논리 0/1로 판정한다. “누르지 않으면 PC13으로 전류가 흘러서 HIGH”라고 설명하기보다 “풀업 저항이 입력 전압을 HIGH로 유지한다”고 이해한다. 실제 보드의 B1과 외부 PC0/PC1/PC3 버튼은 회로와 배선을 각각 확인한다.
GPIO_NOPULL은 MCU 내부 풀업·풀다운을 사용하지 않는 설정이다. 외부 저항으로 입력이 안정화되어 있다면 정상적인 선택이고, 외부 저항도 없으면 입력이 불안정해질 수 있다.
## 5. 반복과 시간: 0.2초마다 토글한다는 뜻
```c
/* GPIO 초기화 이후 main의 반복문 안에서 실행하는 예 */
HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_15);
HAL_Delay(200);
```
반복할 때마다 상태를 뒤집고 약 200 ms 기다린다. ON 200 ms와 OFF 200 ms가 합쳐져 한 번의 전체 깜빡임 주기는 약 400 ms다. 함수 실행 시간과 tick 해상도가 있으므로 정밀 측정용 시간은 아니다.
HAL_Delay() 동안 이 실행 흐름은 다음 버튼 검사로 진행하지 않는다. 버튼 응답성과 표시 갱신을 함께 다루려면 이후 학습하는 HAL_GetTick() 기반 시간 검사나 타이머가 필요하다.
## 6. 클럭 설정을 읽을 때 확인할 점
CPU가 100 MHz로 동작한다고 해서 외부 클럭 자체가 100 MHz라는 뜻은 아니다. HSI/HSE 같은 입력을 PLL로 변환한다. Nucleo의 외부 클럭 공급 경로는 보드 버전과 구성에 따라 확인해야 하며, 항상 별도 8 MHz 크리스털이 실장되어 있다고 단정하지 않는다.
실제 LED_Button_driver의 저장된 SystemClock_Config()는 HSI를 PLL 입력으로 사용한다. 다른 날짜의 HSE 프로젝트 설정과 섞지 않는다.
## 7. 혼자 다시 만드는 순서
1. GPIO 출력 하나를 설정하고 LED 한 개를 켠다.
2. 꺼짐과 토글을 확인한다.
3. 입력 하나의 HIGH/LOW 변화를 디버거로 확인한다.
4. 버튼 입력에 따라 LED 한 개를 제어한다.
5. 마지막에 LED 네 개와 여러 버튼으로 확장한다.
**완료 기준:** 빌드 성공, 다운로드 성공, 실제 핀 동작 확인을 구분해서 말할 수 있다. 사용자 코드는 CubeMX의 USER CODE BEGIN/END 영역에 넣는다.
