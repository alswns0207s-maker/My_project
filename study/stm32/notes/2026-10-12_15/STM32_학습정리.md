| 날짜 | 실습 주제 | 핵심 질문 |
|---|---|---|
| 10/12 | LED·외부 버튼, HAL, 상태별 동작 | 핀을 읽고 출력을 어떻게 바꾸는가? |
| 10/13 | C 자료형·UART 출력, FND 표시 | 숫자를 코드와 출력 패턴으로 어떻게 표현하는가? |
| 10/14 | 4자리 카운터, RUN/STOP/CLEAR, 파일 분리 | 표시를 유지하며 시간과 버튼을 어떻게 처리하는가? |
| 10/15 | 입력 오류 디버깅, 풀업, 베어메탈 GPIO | 실제 핀 상태를 어떻게 확인하고 레지스터로 제어하는가? |

### 먼저 구분할 핀

| 실습 | 입력/출력 핀 | 역할 |
|---|---|---|
| 외부 버튼 실습 | PC0 / PC1 / PC3 | 외부 BTN1 / BTN2 / BTN3; 교구의 BTN0 표기와 코드 이름은 다를 수 있음 |
| 초기 LED 과제 | PB15 / PB14 / PB13 / PC4 | 외부 LED 4개 |
| 베어메탈 실습 | PC13 | 보드 USER/B1 버튼 |
| 베어메탈 실습 | PA5 | 출력 제어 대상, 보드 LD2와 연결된 핀 |
| FND 실습 | PA5 | 첫 번째 자리 선택 D1 |

**PC0와 PC13은 서로 다른 핀이다.** 같은 코드로 두 버튼을 동시에 읽는 것이 아니다. PA5도 실습마다 역할이 다르므로 FND 배선을 유지한 채 LED 실습을 할 때는 같은 핀에 연결된 회로를 함께 고려한다.

## 1. 10/12 — HAL로 LED와 버튼 제어

### 1-1. 프로그램의 기본 실행 순서

```text
HAL_Init()
  → SystemClock_Config()
  → MX_GPIO_Init()
  → while (1)에서 입력 확인과 출력 반복
```

- `HAL_Init()`: HAL 기본 초기화와 기본 시간 기준 준비.
- `SystemClock_Config()`: 시스템 및 버스 클럭 설정.
- `MX_GPIO_Init()`: 포트 클럭, 핀 방향, 풀업·풀다운 등 설정.
- `while (1)`: 프로그램이 끝나지 않고 반복하도록 구성.

### 1-2. GPIO 기본 함수

```c
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_15, GPIO_PIN_SET);   // HIGH
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_15, GPIO_PIN_RESET); // LOW
HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_15);               // 출력 반전
HAL_GPIO_ReadPin(GPIOC, GPIO_PIN_0);                  // 입력 읽기
```

**보충:** HIGH가 항상 LED ON을 뜻하는 것은 아니다. LED와 드라이버의 연결 방식에 따라 LOW일 때 켜질 수도 있다. 코드의 논리값과 실제 회로 동작을 함께 확인해야 한다.

### 1-3. 상태로 동작 나누기

현재 과제 코드에는 `LED_ON`, `LED_OFF`, `LED_TOGGLE` 상태가 있다. 메인 반복문은 `switch (state)`로 해당 상태의 함수를 호출한다.

```text
버튼 읽기 → state 변경 → 해당 상태의 LED 출력 수행 → 반복
```

상태는 프로그램이 현재 무엇을 해야 하는지 저장하는 값이다. 함수는 정의한 순서대로 자동 실행되지 않는다. `main()`이나 다른 함수에서 호출할 때 실행되고 호출한 곳으로 돌아온다.

**보충:** `HAL_Delay(200)` 동안 메인 흐름은 다음 버튼 검사로 진행하지 않는다. 인터럽트까지 모두 멈춘다는 의미는 아니다. 반응성을 높이려면 이후에 배운 tick 비교 방식으로 대기를 대체할 수 있다.

## 2. 10/13 — C 기초와 FND 표시

### 2-1. 자료형과 UART 출력

`2026.10.13_C_Language` 프로젝트에는 USART2와 `printf()` 출력 연결이 있다. 통신 설정은 115200 baud, 8 data bits, no parity, 1 stop bit이다.

```c
int __io_putchar(int ch)
{
    HAL_UART_Transmit(&huart2, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
    return ch;
}
```

이 함수는 출력 문자 하나를 UART로 전달하는 역할을 한다. `printf()`가 PC의 일반 실행 프로그램처럼 자동으로 IDE 콘솔에 나오는 것은 아니며, 출력 경로와 시리얼 수신 환경이 필요하다.

**보충 — C의 문자와 크기:**

```c
printf("%zu\n", sizeof('A'));
```

C에서 `'A'`는 `int` 타입인 문자 상수다. 현재 ARM GCC 환경에서는 보통 4바이트다. `sizeof`의 반환형은 `size_t`이므로 `%zu`가 적절하다. 프로젝트에 남아 있는 `%d` 예제는 이 형태로 정리하는 것이 좋다.

### 2-2. FND는 숫자 그림을 구성하는 LED 묶음

7개 세그먼트 A~G와 소수점 DP의 ON/OFF 조합으로 숫자를 표시한다. 실습 코드의 배열 순서는 **A, B, C, D, E, F, G, DP**다.

예를 들어 숫자 2는 A·B·D·E·G를 켠다.

```c
{1, 1, 0, 1, 1, 0, 1, 0} // 숫자 2
```

실습 드라이버는 세그먼트 HIGH=ON, 자리 선택 LOW=ON이라는 가정으로 작성되어 있다. 실제 FND 극성과 드라이버 회로는 부품에 따라 확인해야 한다.

### 2-3. 실습 GPIO 매핑

| 신호 | 핀 | 신호 | 핀 |
|---|---|---|---|
| A | PA6 | B | PA9 |
| C | PB5 | D | PB10 |
| E | PA8 | F | PA7 |
| G | PB3 | DP | PB4 |
| D1 | PA5 | D2 | PB6 |
| D3 | PC7 | D4 | PA10 |

### 2-4. 4자리 멀티플렉싱

```text
전체 자리 OFF
  → 해당 자리의 세그먼트 패턴 설정
  → 해당 자리만 ON
  → 짧게 유지
  → 다음 자리로 반복
```

네 자리를 빠르게 번갈아 켜면 동시에 켜진 것처럼 보인다. 패턴 변경 전에 자리를 끄면 이전 숫자가 다른 자리에 잠깐 비치는 현상을 줄일 수 있다.

자리 분리는 나눗셈과 나머지를 사용한다.

```c
thousands = (number / 1000) % 10;
hundreds  = (number / 100)  % 10;
tens      = (number / 10)   % 10;
ones      = number % 10;
```

**보충:** 초기 FND 파일에는 `main()` 안에 함수가 정의된 형태가 남아 있다. GNU C 확장으로 허용되는 경우가 있지만 표준 C 방식은 아니므로, 함수 정의는 `main()` 밖에 두고 호출만 안에서 하는 방식으로 정리한다.

## 3. 10/14 — FND 카운터와 파일 분리

### 3-1. 목표

`0000 → 0001 → … → 9999 → 0000`으로 증가하며, 카운터가 정지해도 FND 스캔은 계속 수행한다.

```c
if ((uint32_t)(HAL_GetTick() - previousTick) >= 100U)
{
    previousTick += 100U;
    counter = (counter + 1U) % 10000U;
}
// 반복문에서 FND 출력도 계속 호출
```

**보충:** `> 100U`는 1ms tick 기준 최소 101ms가 지나야 참이다. 100ms 경과 조건은 `>= 100U`이다. 반복문 실행 시간 때문에 실제 처리 시점에는 지연이 있을 수 있다. `HAL_Delay(1)`도 정확한 1ms 하드웨어 타이머 스캔과 동일하지 않다.

### 3-2. RUN / STOP / CLEAR

| 상태 | 동작 | 초기 코드의 입력 처리 |
|---|---|---|
| STOP | 현재 숫자 표시 유지 | PC0 → RUN, PC1 → CLEAR |
| RUN | 숫자 증가 및 표시 | PC0 → STOP |
| CLEAR | 숫자를 0으로 설정 | 처리 후 STOP으로 복귀 |

초기 상태는 STOP이다. 실행 중 PC1을 검사하지 않는 코드는 실행 중 초기화 버튼에 반응하지 않는다. 이는 입력이 안 들어오는 문제와 구분해야 한다.

**보충 — 누름과 눌린 순간은 다르다:** LOW인 동안 매번 RUN↔STOP을 전환하면 한 번 길게 눌러도 여러 번 전환된다. 디바운싱은 접점의 빠른 흔들림을 처리하고, 에지 검출은 안정된 해제→눌림 변화에서 한 번만 이벤트를 만든다. 이번 배선 오류의 직접 원인과는 별개의 개선 사항이다.

### 3-3. 파일 역할

| 파일 | 역할 |
|---|---|
| `main.c` | 초기화, 카운터와 상태 처리, 드라이버 호출 |
| `fnd.h` | 외부에서 사용할 함수 선언 |
| `fnd.c` | 숫자 패턴, GPIO 매핑, 자리 스캔 구현 |

`#include`는 헤더 내용을 포함할 뿐, 해당 `.c` 파일을 자동으로 컴파일 대상으로 만드는 명령은 아니다. 헤더 검색 경로와 소스의 빌드 포함을 따로 확인한다.

### 3-4. 실제 발생한 빌드 문제

- 증상: `fatal error: fnd.h: No such file or directory`.
- 당시 실제 파일: `STM32CubeIDE/Application/User/Core/driver/fnd/fnd.h`.
- 잘못된 Include 경로: `STM32CubeIDE/Drivers/fnd`.
- 조치: 실제 디스크 위치에 맞게 Debug/Release Include 경로 수정.
- 함께 수정: 숫자 2 패턴의 G 세그먼트 누락.
- 결과: 해당 시점 Debug/Release 컴파일·링크 오류 0, 경고 0 확인.

**프로젝트 구조 변경 주의:** 이후 프로젝트가 다시 구성되며 현재는 `Core/Src/driver/fnd` 경로를 사용하는 버전이 있다. 예전 경로를 현재 설정에 무조건 적용하면 안 된다. IDE의 논리적 폴더와 실제 경로를 구분한다.

## 4. 10/15 — 버튼 입력 오류 디버깅

### 4-1. 실행 문제와 입력 문제 구분

```text
Debug 시작 → main에서 정지 → F8로 계속 실행
  → 버튼 검사에 브레이크포인트
  → Expressions에서 입력 비트 확인
```

Debug에서 멈춘 상태는 코드가 실행 중인 상태가 아니다. FND가 한 자리만 켜진 채 멈춘 것은 CPU 정지로 자리 스캔도 멈췄기 때문이다.

### 4-2. 실제로 확인한 입력값

PC0는 아래 식으로 읽었다.

```c
(GPIOC->IDR & 1U)
```

| 단계 | 버튼 뗌 | 버튼 누름 | 근거 |
|---|---|---|---|
| 수정 전 | 0 | 0 | 디버거 값 및 사용자 확인 |
| 외부 저항 제거 + 내부 풀업 적용 | 1 | 0 | 디버거 값 및 사용자 확인 |
| 외부 풀업으로 변경 + 내부 풀업 해제 | 정상 동작 보고 | 정상 동작 보고 | 사용자가 해결했다고 확인; 최종 두 상태 캡처는 별도 필요 |

브레이크포인트에서 손 상태만 바꾼 경우 화면의 값이 바로 갱신되지 않을 수 있다. 다시 실행하여 멈추거나 명시적으로 값을 새로 읽어 비교한다.

### 4-3. 원인과 해결

배선 설명과 사진상 저항이 GND로, 버튼 반대쪽도 GND로 연결된 것으로 판단했다. 두 상태 모두 입력을 LOW로 만드는 경로만 있고 HIGH로 유지할 경로가 없었다.

```text
수정 전 판단
PC0 ── 저항 ── GND
 └── 버튼 ── GND

외부 풀업으로 수정
3.3V ── 저항 ──┬── PC0
                │
               버튼
                │
               GND
```

진단 중에는 외부 저항을 제거하고 `GPIO_PULLUP`을 적용했다. 해제=1, 눌림=0으로 변해 입력을 구별할 수 있었다. 이후 외부 저항을 + 레일로 옮기고 내부 설정을 원래 `GPIO_NOPULL`로 되돌렸다. 사용자가 정상 동작을 보고했다.

**확인하지 못한 항목:** 최종 사용 저항의 실측값과 + 레일 전압은 대화에서 확정되지 않았다. 정리 자료에 ‘10kΩ을 사용했다’고 단정하지 않는다. 10kΩ은 풀업 회로 설명용 예시다.

### 4-4. 풀업과 Push-pull 구분

| 용어 | 의미 |
|---|---|
| 풀업 | 입력을 사용하지 않을 때 HIGH로 유지하는 저항 연결 |
| 풀다운 | 입력을 사용하지 않을 때 LOW로 유지하는 저항 연결 |
| Push-pull | 출력 회로가 HIGH와 LOW를 모두 구동하는 방식 |
| Open-drain | 출력 회로가 LOW를 구동하고, 꺼지면 고임피던스가 되는 방식 |

외부 버튼에 풀업 저항을 사용했다고 PC0가 Open-drain 출력이 되는 것은 아니다. 이 실습의 버튼 핀은 입력이다.

## 5. 10/15 — 레지스터와 비트 연산

### 5-1. 먼저 비트 연산 이해하기

| 식 | 의미 |
|---|---|
| `1U << n` | n번 비트만 1인 마스크 만들기 |
| `reg |= (1U << n)` | n번 비트를 1로 설정 |
| `reg &= ~(1U << n)` | n번 비트를 0으로 설정 |
| `(reg >> n) & 1U` | n번 비트를 0 또는 1로 읽기 |

비트 번호는 오른쪽부터 0이다. `a |= b`는 `a = a | b`, `a &= b`는 `a = a & b`의 축약이다.

`|= ~(1U << n)`은 n번 비트를 제외한 나머지를 모두 1로 만들므로 ‘n번만 켜기’가 아니다. C의 왼쪽 시프트는 `<<`이고 `<<<`는 없다.

### 5-2. 주소로 하드웨어 접근하기

```c
*(volatile uint32_t *)(0x40020000UL + 0x00UL)
```

- `0x40020000`: GPIOA 시작 주소.
- `+0x00`: MODER의 오프셋.
- `uint32_t *`: 32비트 데이터에 접근하는 포인터 타입으로 해석.
- 맨 앞 `*`: 해당 주소의 값에 접근하는 역참조.
- `volatile`: 컴파일러가 하드웨어 접근을 불필요하다고 판단해 생략하지 않도록 지정.

**보충:** `volatile`은 원자적 연산이나 인터럽트 간 동기화를 보장하는 기능은 아니다.

```c
#define REG(addr) (*(volatile uint32_t *)(addr))
#define GPIOA_MODER REG(GPIOA_BASE + 0x00UL)
```

이 매크로는 긴 주소 접근식에 이름을 붙인다. 매크로 정의 자체가 레지스터 값을 바꾸지는 않는다.

### 5-3. 클럭을 먼저 켜야 하는 이유

주변장치 클럭을 사용하지 않을 때 차단하면 내부 신호 전환에 드는 전력을 줄일 수 있다. GPIO 설정 전에 해당 포트의 클럭을 활성화한다.

```c
RCC_AHB1ENR |= (1U << 0); // GPIOA
RCC_AHB1ENR |= (1U << 2); // GPIOC
(void)RCC_AHB1ENR;        // 활성화 후 읽기
```

클럭 차단은 핀의 LOW 출력이나 전원 차단과 같은 뜻이 아니다. HAL의 `__HAL_RCC_GPIOA_CLK_ENABLE()`도 같은 목적의 설정을 수행한다.

### 5-4. GPIO 레지스터 지도

| 레지스터 | 오프셋 | 핀 하나당 비트 | 역할 |
|---|---|---|---|
| MODER | 0x00 | 2 | 입력·출력·대체 기능·아날로그 |
| OTYPER | 0x04 | 1 | Push-pull / Open-drain |
| OSPEEDR | 0x08 | 2 | 출력 전환 속도 |
| PUPDR | 0x0C | 2 | 내부 풀업·풀다운 |
| IDR | 0x10 | 1 | 실제 입력 상태 읽기 |
| ODR | 0x14 | 1 | 출력 래치 상태 |
| BSRR | 0x18 | 설정/해제 각각 1 | 특정 출력 비트 설정·해제 |

**PA5 모드**는 MODER의 11·10번 비트이고, **PC13 모드**는 27·26번 비트다. 반면 IDR·ODR에서 PA5는 5번, PC13은 13번 비트를 사용한다.

OSPEEDR의 속도는 LED가 깜박이는 주기가 아니라 출력 전압의 전환 특성이다. 점멸 간격은 대기·타이머 코드가 결정한다.

## 6. 구조체와 함수로 GPIO 제어하기

### 6-1. 구조체를 사용하는 이유

레지스터를 4바이트 간격의 멤버로 나열하면 실제 하드웨어 배치와 대응시킬 수 있다.

```c
typedef struct {
    volatile uint32_t MODER;
    volatile uint32_t OTYPER;
    volatile uint32_t OSPEEDR;
    volatile uint32_t PUPDR;
    volatile uint32_t IDR;
    volatile uint32_t ODR;
    volatile uint32_t BSRR;
    volatile uint32_t LCKR;
    volatile uint32_t AFRL;
    volatile uint32_t AFRH;
} gpio_regs_t;

#define GPIOA ((gpio_regs_t *)GPIOA_BASE)
```

`GPIOA->MODER`는 `(*GPIOA).MODER`와 같다. 주소에 구조체 모양으로 접근하므로 매번 오프셋을 직접 적을 필요가 없다.

### 6-2. 함수별 역할

| 함수 | 기능 | 예시 |
|---|---|---|
| gpio_set_mode | 핀 모드 설정 | `gpio_set_mode(GPIOA, 5, GPIO_MODE_OUT)` |
| gpio_set_pull | 풀업·풀다운 설정 | `gpio_set_pull(GPIOC, 13, GPIO_PULL_UP)` |
| gpio_read | 입력을 0/1로 반환 | `gpio_read(GPIOC, 13)` |
| gpio_write | 출력을 HIGH/LOW로 설정 | `gpio_write(GPIOA, 5, 1)` |
| gpio_toggle | 현재 출력을 반전 | 현재 main에서는 호출하지 않음 |

이 사용자 함수의 `pin`은 0~15의 **핀 번호**다. HAL의 `GPIO_PIN_13` 같은 **비트 마스크**를 인수로 넣으면 안 된다.

### 6-3. 설정 함수의 공통 순서

```c
uint32_t v = port->MODER;                    // 읽기
v &= ~(3U << (pin * 2U));                    // 해당 2비트 지우기
v |= ((uint32_t)mode << (pin * 2U));         // 새 설정 넣기
port->MODER = v;                            // 저장
```

`3U`는 이진수 `11`이다. 핀당 2비트이므로 `pin * 2`만큼 이동한다. `gpio_set_pull()`도 같은 방식이며 이동 위치는 `pull * 2`가 아니라 **`pin * 2`**다.

### 6-4. BSRR로 출력하기

```c
port->BSRR = level ? (1U << pin) : (1U << (pin + 16U));
```

- 하위 0~15번 비트에 1을 쓰면 해당 출력이 HIGH가 된다.
- 상위 16~31번 비트에 1을 쓰면 해당 출력이 LOW가 된다.
- PA5를 켤 때는 5번, 끌 때는 21번 비트에 1을 쓴다.

**보충:** BSRR은 출력 래치를 읽고 수정해 다시 쓰지 않고도 특정 비트를 바꿀 수 있다. 하지만 ODR을 먼저 읽는 사용자 `gpio_toggle()` 전체가 인터럽트와 무관하게 원자적인 것은 아니다.

### 6-5. 최종 베어메탈 실습의 실행 흐름

```text
main()
 → GPIOA·GPIOC 클럭 활성화
 → PA5 초기 LOW, Push-pull
 → PA5 출력 모드
 → PC13 입력 모드 + 내부 풀업
 → 반복: PC13=0이면 PA5 HIGH, PC13=1이면 PA5 LOW
```

이 실습은 보드 USER 버튼 PC13을 사용한다. 앞선 외부 버튼 PC0 배선 실습과 별개다. 현재 프로젝트의 전체 코드 사본은 `baremetal_gpio_reference.c`에 보관했다. 이번 정리 작업에서는 코드를 다시 빌드하거나 보드 동작을 검증하지 않았다.

## 7. 오류와 해결 요약

| 증상/실수 | 원인 | 해결 |
|---|---|---|
| fnd.h를 찾지 못함 | 실제 위치와 Include 경로 불일치 | 디스크 경로와 빌드 설정 비교 |
| delay 암시적 선언 오류 | 함수 선언 없이 호출 | 정의를 main 위에 두거나 프로토타입 추가 |
| Debug 후 동작 안 함 | main 또는 breakpoint에서 정지 | F8로 계속 실행 |
| FND 한 자리만 켜짐 | 디버거 정지로 스캔 정지 | 입력 확인 후 breakpoint 해제·실행 |
| 버튼을 떼도 눌러도 0 | 풀업 경로가 없는 배선으로 판단 | 내부 풀업으로 검증 후 외부 풀업 수정 |
| GPIO 설정이 반영되지 않음 | 클럭 활성화까지 주석 처리 | 함수 호출 전에 RCC 설정 복원 |
| PC13을 누르는데 무반응 | PC0를 읽는 코드 사용 | 모드·풀업·입력 검사를 PC13으로 통일 |
| PC13 모드 설정 오류 | PC5용 10·11번 비트 수정 | PC13용 26·27번 비트 수정 |
| 조건이 항상 거짓 | `IDR & mask == 0` 연산 우선순위 | `(IDR & mask) == 0` |
| 다른 핀 설정까지 변경 | `|= ~mask` 사용 | 켤 때 `|= mask`, 끌 때 `&= ~mask` |
| pull 설정 위치가 틀림 | `pull * 2`만큼 이동 | `pin * 2`로 수정 |
